# Architecture and feature boundaries

`Program.cs` owns process startup, single-instance activation and the WPF dispatcher loop. `Widget.cs` is the main WPF window: the Now card, profile tiles, device lists, Settings and profile-editor pages, status toast, tray icon/menu, current-user startup preference and UI-thread notifications. `Flyout.cs` is the tray quick-switch panel; it renders from the window's snapshot and settings and routes every switch through the same `ApplyProfile`/`ApplyDevices` path.

`Theme.cs` and `Theme.xaml` hold the visual system. The XAML resource dictionary (embedded and parsed at startup, so `build.ps1` needs no XAML compiler) defines the button, scrollbar, text box, toggle and tooltip templates and the palette. Accent brushes are replaced at runtime: Audio Me teal by default, or the Windows accent (`AccentPalette` Light 2 shade, lifted for contrast on dark glass) when the user chooses Match Windows; text on accent fills picks black or white by luminance. `Theme.ApplyBackdrop` requests the DWM acrylic backdrop (attribute 38), extends the frame and removes `WS_SYSMENU` so DWM doesn't draw caption buttons over the custom title bar; where the attribute is rejected or Transparency effects are off, windows paint a solid surface. Setting, accent and theme broadcasts re-apply the backdrop and accent.

`Models.cs` contains persisted models, settings saves/recovery, profile availability and six-role matching, and `IAudioService`. `WindowsAudioService` creates and disposes COM objects on the worker thread that uses them; the UI never shares a COM object between threads. Read/switch tasks explicitly use the default background scheduler. Completion callbacks use the form's BeginInvoke dispatcher rather than an ambient synchronization context, keeping redraws on the owning UI thread even during nested/test message loops. Only one manual switch is accepted at a time, exit is held during a switch, and a possibly stale polling result is ignored while switching.

Role chips are noninteractive and expose role/state accessible names plus tooltips. `UiElements.cs` keeps the dark color table for the WinForms tray context menu. The app never modifies Windows theme settings. The Now card is derived from each snapshot; it is not a persisted last-used name. Profile tiles share the row evenly up to three profiles; beyond that they keep a fixed width and the row scrolls horizontally with eased mouse-wheel scrolling.

`Audio.cs` retains availability prechecks for the entire requested set, per-role writes, read-back verification, prior-default snapshots and verified restoration attempts. This reliability layer is not a paid capability.

Legacy XML fields `Profiles`, `Favorites`, `Deemphasized`, `Pinned`, `WindowWidth`, and `WindowHeight` are retained; `Accent` (settings) and `Icon` (profile) were added in 1.2 and older builds preserve them as unknown elements. Window size is stored in device-independent pixels. Deemphasized devices now appear under Other devices. Endpoint references are never replaced based on similar hardware names. Optional saved hardware names improve offline explanations; aliases affect presentation only. Unknown XML elements are preserved. Invalid or unreadable settings block writes until explicit backup/reset; normal saves retain the previous file.

## Free boundary

Manual device/profile selection, profile editing, favorites, aliases, organization, accent color, the tray flyout, startup preference, tray access, remembered size, status/error feedback, verification/restoration, keyboard navigation and accessibility remain free. No activation check gates these paths.

## Planned premium boundary

There are no global hotkey listeners, process watchers, application triggers, multi-device audio mirroring, entitlement checks, accounts or payment code in this version. Settings lists them as Planned. The free app is MIT-licensed; premium modules are intended to live outside this repository and plug in through the coordinator below. Future premium trigger adapters should submit explicit requests through a shared operation coordinator backed by `IAudioService`, rather than writing Windows defaults directly. That coordinator should serialize operations, retain full prior role assignments, handle cancellation/disconnection, and marshal UI changes safely. An entitlement policy should gate trigger registration only, leaving free manual commands and accessibility intact.

Multi-device output would mirror the default endpoint via WASAPI loopback capture into additional render endpoints, with drift correction; no virtual audio driver is planned. A free option to route Calls to a separate device needs role-specific writes in `Audio.Apply` and six-role matching per role. Trigger precedence, overlapping apps, restoring previous defaults only when appropriate, and sleep/resume rules need a separate design before automation is enabled. Do not silently substitute unavailable devices. Keep licensing/payment implementation separate from audio service and profile storage.

## Tests

`ConnectionTests.cs` exercises sorting, preferences, window dimensions, backward compatibility and rejecting an invalid endpoint before any write. `StateTests.cs` validates migration, availability/reconnection, split roles, malformed settings, explicit recovery and exact backups in temporary directories. `UiChecks.cs` injects a fake service and isolated settings into the real window, checks tiles, role chips, accent switching, horizontal profile scrolling, the flyout, Settings/About, offline editing and editor focus, renders layouts to `bin/ui-validation`, and holds a simulated switch to verify UI responsiveness. `-Screenshots` shows demo windows over a stand-in wallpaper and captures the composited glass for the README. It never writes live defaults or enables startup.
